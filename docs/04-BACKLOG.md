# 04 · Backlog（這次不做）

這份清單的用途是**保護你不要在 Hackathon 期間加功能**。

想到好點子的時候，寫進這裡，然後回去做原本的事。

---

## 賽事期間明確不做

| 項目 | 為什麼不做 |
| --- | --- |
| 帳號 / 登入 | 零安裝零註冊是產品賣點，加了反而變差 |
| 資料庫與雲端儲存 | Demo 不需要，照片存在瀏覽器記憶體即可 |
| 多語系 | 評審都懂中文 |
| 桌機版適配 | 使用場景就是手機 |
| 深色模式 | 沒有加分 |
| 拍完自動修圖 | 這是另一個產品，會模糊焦點 |
| 影片模式 | 範圍太大 |
| 自訂版型編輯器 | 有價值但吃時間，屬於下一版 |
| 上架平台 API 串接 | 需要授權流程，來不及 |

---

## 賽後值得做的（依價值排序）

### 高價值

**1. 版型依商品類別自動切換**
賣鞋、賣衣服、賣 3C、賣書，構圖慣例不同。
先讓 VLM 判斷商品類別，再載入對應的版型組。

> 這個其實在賽事期間就可能做得到，如果 Phase 3 提早完成可以試。

**2. 從成交資料回頭學版型**
哪些版型的商品成交率高？把這個資料收回來，
版型就從「設計師的直覺」變成「資料驗證過的最佳解」。
**這是這個產品真正的護城河。**

**3. 瑕疵引導**
二手交易最大的糾紛來源是瑕疵沒拍清楚。
系統主動提示「這裡看起來有磨損，建議補一張特寫」。

**4. 一鍵上架**
拍完直接推到蝦皮 / 旋轉拍賣，含標題、描述、多張照片。

### 中價值

**5. 語音下指令**（台灣本土 ASR）
國網有 `Breeze-ASR-26`、`Taiwan-Tongues-ASR-CE`、
`NUTN-KWS-Faster-Whisper-Taiwanese`。
使用者說「我要拍球鞋」，系統切換版型。
**台灣評審會有反應，但優先序放最後。**

**6. 光影引導**
不只判斷光好不好，而是告訴使用者「往窗邊移三步」。

**7. 批次模式**
賣家一次要拍二十件商品，做成連續流程。

**8. 背景移除與替換**
純色背景是商品照的基本要求。

### 低價值 / 探索性

**9. 進階物件偵測**
COCO-SSD 只認 80 類。要認得更細（球鞋 vs 皮鞋）需要換模型。

**10. 3D 姿態引導**
不只平面位置，還包含物件該轉幾度。

**11. 桌面配置建議**
不只講物件，還講「換一張淺色桌布」。

## 已知技術債

| 項目 | 影響 | 修的成本 |
| --- | --- | --- |
| 版型座標是手寫的，沒有驗證工具 | 改版型要靠肉眼 | 中 |
| `phrases.js` 文案與語音檔沒有自動對應檢查 | 可能播到不存在的檔 | 低 |
| 偵測框平滑用簡單移動平均 | 快速移動時會延遲 | 中 |
| 沒有錯誤上報 | 出問題只能看 console | 低 |
| VLM 回應沒有快取 | 同樣場景重複付費 | 低 |

---

## 想到新點子時的判斷流程

```
這個點子會讓 Demo 更好看嗎？
  ├─ 不會 → 寫進 Backlog，回去做原本的事
  └─ 會 → 它需要幾小時？
        ├─ 超過 2 小時 → 寫進 Backlog
        └─ 2 小時內 → 目前的階段做完了嗎？
              ├─ 沒有 → 寫進 Backlog
              └─ 做完了 → 可以做
```
