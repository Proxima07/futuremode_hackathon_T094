## 一、主體明明在框裡，卻說「把要拍的東西放到鏡頭前」

`web/js/planner/planStabilizer.js` 的這一行：

```js
if (!plan.placements?.length) alignment = "lost";
```

`GUIDING_SYSTEM` 的重點是回 `move / ready / lost`，
**`placements` 只是附帶欄位，模型很容易省略。**

於是模型明明說了 `ready`，卻因為沒填 `placements`
被前端改判成 `lost`，提示退回「把要拍的東西放到鏡頭前」——
但主體其實好好地在框裡。

**修法：引導階段目標早就鎖定了，我們已經知道主體是什麼。**
空的 `placements` 更可能是「模型沒寫」而不是「東西不見了」。

現在的規則：

| 情況 | 處理 |
| --- | --- |
| 模型明確說 `lost` | 照舊，連續兩次才重新規劃 |
| `move` / `ready` 但沒填 placements | **沿用上一次已知的主體** |
| 全新工作階段、還沒有已知主體 | 保守地當成不見 |

鎖定當下就會記住主體，重新規劃時會清掉，
不會把上一個場景的物件名稱帶到新場景。

## 二、手抖被當成明確位移

`comparePreviewFrames` 原本只容許 **±1 個縮圖像素**的整體平移。

32×32 的一個像素約是畫寬的 **3%**——手持拍攝隨便晃一下就超過。

而且 `_observePreview` **單幀比對就直接宣告移動**，
沒有連續確認。一次手滑，引導提示就被清掉、
可拍攝狀態就被撤銷。

**兩處都修：**

**搜尋半徑放寬到 ±3 像素（約畫寬 9%）**

| 平移量 | 舊（半徑 1） | 新（半徑 3） |
| --- | --- | --- |
| 3% | 同一畫面 | 同一畫面 |
| 6% | **判定移動** | 同一畫面 |
| 9% | **判定移動** | 同一畫面 |
| 13% | 判定移動 | 判定移動 |
| 19% | 判定移動 | 判定移動 |

真正的移動（轉向、換物件、走動）遠大於 9%，仍然抓得到。

代價是每次比較從 9 個位移試到 49 個。
32×32 只有一千個像素，即使 49 次也不到一毫秒。

**連續兩次確認才算移動**

取樣間隔 250ms，連續兩次約 0.5 秒。
對「使用者真的把鏡頭移開了」來說反應仍然夠快，
但手震那種單幀跳動不會再打斷流程。

**可調參數**（`web/js/lib/config.js`）：

```javascript
MOTION: { threshold: 16, radius: 3, confirmations: 2 },
```

覺得反應太遲鈍就把 `radius` 或 `confirmations` 調小。

## 三、v0.34 的內容（一併包含）

### 修 v0.33 定不下來

```js
const lightReady = !!light && light.verdict !== "problem";
```

`!!light` 是關鍵。v0.32 起光線分析改成「只在首次或明顯變化時
才呼叫」，最短間隔 15 秒。所以光線還沒回來時 `lightReady`
就是 `false`——構圖對好了也永遠卡在「確認光線中」，快門不變綠。

改成只有明確判定有問題才擋，未知一律視為可拍。

### 提示停留更久

| 參數 | 舊 | 新 |
| --- | --- | --- |
| `GUIDANCE_HOLD_MS` | 5000 | **7000** |
| `STABILITY.adviceRefreshMs` | 1000 | **2500** |

只影響文字切換的時機，不減慢背景判斷。

### 補光提醒更早

| 參數 | 舊 | 新 |
| --- | --- | --- |
| `darkMean` | .20 | **.28** |
| `darkSubject` | .26 | **.34** |
| `backlitSubject` | .28 | **.36** |
| `backlitRatio` | .55 | **.62** |

提示詞也加了「勉強看得出來不等於亮度足夠」。

### 縮放改成兩指手勢

新增 `web/js/ui/pinchZoom.js`。滑桿改成手勢，
只在縮放時淡入倍率標示，一秒後消失。
`.env` 設 `PINCH_ZOOM=false` 可切回滑桿。

### 介面開關移到 .env

新增 `GET /api/ui-config`：

```
SHOW_ANALYSIS_STATUS=false   # 「持續判斷中」那條狀態列
ALLOW_DEBUG_PANEL=true       # 按 D 的除錯面板
PINCH_ZOOM=true              # 兩指手勢縮放
```
