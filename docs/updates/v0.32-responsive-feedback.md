# v0.32：讓構圖回饋跟上目前畫面

本包以 v0.31 為基礎，只包含本次修改／新增的檔案，保留專案原有資料夾結構。

## 查到的問題

v0.31 會比較「送出模型的照片」與「收到回覆時的畫面」，差異大就捨棄回覆。原本的逐像素比較容易把高紋理背景上的小幅手震當成明顯移動。請求因此持續成功，結果卻可能一直沒有被採用。

畫面上的「最近判斷」取自上次採用結果的時間；新請求開始又會把過期狀態蓋回「判斷中」，使真正的等待原因不清楚。另一方面，後端也可能回傳 HTTP 200 加上 `fallback: true`，這表示分析失敗，並不是可用的新判斷。單靠 HTTP log 不能區分這兩種原因。

## 本次行為

1. **更快回應移動。** 本機每 250ms 比較小縮圖，偵測明顯移動時先收起舊的移動指示和「可以拍攝」，顯示「位置已改變，停穩一下確認是否到位」。正在執行的模型請求繼續完成，不因每次本機取樣而反覆取消。
2. **容許小幅手震。** 比較 32×32 灰階縮圖時，容許一個縮圖像素的整體平移，並補償整體曝光差異。大幅移動仍不採用舊回覆；超過五秒才回來的來源照片也不直接當成目前已對準。
3. **分開記錄收到與採用。** 狀態列的「回覆 X 秒前」只表示收到回覆的時間；畫面已改變時會同時明示正在確認新位置。HTTP 200 的 fallback 顯示「分析未完成」。除錯面板保留收到、採用、捨棄、fallback 次數，以及補償前後的畫面差異，方便追查。
4. **維持固定目標。** 移動只清除舊的對準證據，構圖線、交點、對準部位繼續固定。重新取得足夠的有效判斷後才進入可拍攝狀態。模型提議改方向、尚待第二次確認時，顯示先保持位置，不再把舊方向的指示放回畫面。同方向提示最多每秒更新一次。
5. **光線由變化觸發。** 每秒只在本機計算曝光統計。首次，或亮度、色彩、光線方向、過曝／過暗比例明顯變化，連續三次觀察成立後才排入光線分析。小幅波動、單次閃光與持續移動不立即觸發。
6. **把排程留給構圖。** 移動後重新確認及對準共識優先。光線優先利用空檔；有待處理的光線事件而構圖持續佔用時，累積八次採用的構圖結果才讓光線插入。光線分析之間至少隔十五秒，失敗採退避重試。光線不變時不再每六秒或三十秒強制分析。

光線分析的基準會在啟動相機、切換鏡頭、切換拍攝情境時重設。單純移動、縮放或重新確認構圖會保留基準。已可拍攝時，新的光線結果仍可更新亮度提醒，但不重新要求變換拍攝角度。

## 時間與限制

- 遠端構圖維持「開始到開始約一秒」的目標，同時最多一個模型請求。若推論本身超過一秒，就在完成後盡快送目前畫面；不累積舊影格佇列。光線／動態構圖分析及錯誤退避仍可能暫時拉長間隔。
- 250ms 是本機畫面變動檢查的設定，不代表模型每 250ms 判斷一次；實際執行也受手機負載與瀏覽器分頁狀態影響。
- 灰階比對是近似的畫面新鮮度檢查，不是物件追蹤或對準偵測。光線統計也可能受大面積物品、背景變動影響。是否真的對準仍由模型配合既有共識機制決定。
- 五秒來源照片上限可透過 `web/js/lib/config.js` 的 `PLAN_MAX_FRAME_AGE_MS` 調整。若實際模型持續需要五秒以上，本版會顯示正在取得新判斷；仍需改善模型端延遲才能得到即時可拍攝結論。
- 已做離線測試，尚未在你的手機或 Gemma 服務上實測。

## 套用方式

1. 在已有 v0.31 的專案根目錄解壓縮本包，合併並覆蓋同名檔案。
2. 本包包含 `web/`、`tests/`、`docs/updates/`；不要整個刪除原有資料夾。
3. 網頁檔案更新後，在手機重新載入頁面。若使用容器映像包入靜態檔案，需按原本流程重建／更新容器。載入版本應為 `v0.32`。
