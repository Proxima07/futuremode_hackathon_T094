## Phase 0 · 地基

**時間：** 9/4 晚（約 3 小時）

### 目標

回答兩個決定生死的問題，並且產出完全不依賴環境的核心資產。

### 範圍

**做：**
- 驗證國網 API 從公網打得通
- 測量往返延遲
- 寫出四個版型的座標
- 建立專案骨架、確認手機能開相機

**不做：**
- 任何 UI 美化
- 任何 AI 邏輯

### 產出

- `scripts/bench_vlm.py` 的實測數字
- `web/src/layouts/definitions/` 四個檔案
- 可跑的 Vite + FastAPI 骨架
- 手機能透過 Tunnel 看到即時畫面

### 驗收標準

- [ ] curl 打國網 API 能拿回 JSON
- [ ] 延遲中位數有實際數字（跑 10 次）
- [ ] 手機瀏覽器看得到自己的相機畫面
- [ ] 四個版型的座標畫在紙上或畫面上看起來合理

### 風險與應對

| 風險 | 機率 | 應對 |
| --- | --- | --- |
| 國網從公網打不到 | 中 | 後端改架在校內機器，用 Tunnel 打出來 |
| **延遲 > 2 秒** | 中 | 三張牌：換 Phi-4-multimodal / 圖壓到 384 / 改成停頓才觸發 |
| 完全連不上 | 低 | 主力改用 GMI Cloud（本來就有 credits，也是評分項） |

> **延遲超過 2 秒不是災難，因為規則層本來就零延遲。**
> 最壞的情況是 AI 修正變成「按鈕觸發」而不是自動，產品依然成立。

## Phase 1 · 離線可用的完整產品

**時間：** 9/5 上午（約 6 小時）

### 目標

**做出一個不需要任何 AI 就能用的產品。**

這是整個專案的保命階段。這一關過了，你就一定有東西可以 Demo。

### 範圍

**做：**
- 相機串流 + 抽幀
- COCO-SSD 物件偵測
- `rulePlanner` 規則指派（高放後、低放前）
- `OverlayCanvas` 疊出目標框
- 對齊判斷 + 變色回饋
- 快門 + 存檔

**不做：**
- 不呼叫任何遠端 API
- 不做語音
- 不做前後對比

### 產出

一個能完整跑完「打開 → 對齊 → 拍照」的網頁。

### 驗收標準

- [ ] 手機打開網頁，鏡頭對著桌上兩三樣東西
- [ ] 畫面出現目標框，**框的位置符合高放後低放前**
- [ ] 把東西移進框裡，框變綠
- [ ] 全部對齊後，快門變成可按
- [ ] 按下去有拍到照片

### 風險與應對

| 風險 | 應對 |
| --- | --- |
| COCO-SSD 認不出桌上的東西 | 準備幾樣它一定認得的物件當 Demo 道具（瓶子、書、杯子、手機、剪刀） |
| 偵測框抖動嚴重 | 對框做時間平滑（移動平均），不要每幀直接用 |
| 對齊永遠對不準 | **容忍值調鬆一點**，寧可讓它容易成功 |

### 實際紀錄

## Phase 2 · 接上 AI

**時間：** 9/5 下午（約 5 小時）

### 目標

讓 AI 修正規則的判斷，並且**確保它掛掉的時候產品不會死**。

### 範圍

**做：**
- `server/routers/plan.py` 主路徑
- `services/vlm/nchc.py` 國網串接
- `services/chain.py` fallback 串
- `services/validate.py` 四道防呆
- `remotePlanner` + `merge` 平滑過渡
- 三種模式的隱藏切換開關

**不做：**
- `advice.py` 輔助路徑（延後到有餘裕再做）

### 產出

`hybrid` 模式可用：規則先給框，AI 回來後平滑修正。

### 驗收標準

- [ ] 打開相機立刻有框（不等 AI）
- [ ] 約 1.5 秒後框會平滑調整
- [ ] **拔掉網路，產品照樣完整可用**
- [ ] 隱藏開關能切到 `rule` 模式
- [ ] 故意送壞資料，後端會擋下來不會傳給前端

### 風險與應對

| 風險 | 應對 |
| --- | --- |
| VLM 輸出不是純 JSON | `validate.py` 前先做清洗（去除 markdown 圍欄） |
| 模型指派得很怪 | prompt 裡給 2 到 3 個範例；仍然怪就降低 AI 的權重 |
| 框跳動太劇烈 | `merge.js` 拉長過渡時間；設定最小變動門檻才更新 |

## 停損規則

**任何一個階段超時 50%，立刻砍範圍進入下一階段。**

理由：評分標準有「技術執行力」和「使用者體驗」，
**這兩項只有完成的東西拿得到分。**

一個做完的普通產品，會打敗一個做不完的絕妙產品。
